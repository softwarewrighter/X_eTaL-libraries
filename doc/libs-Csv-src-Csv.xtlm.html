ᵐc̲olumns< : Char -> Char -> Char

macro · line 51

"city:text population:number" cs:c_olumns< "t": the columns of table t (a table as cs:r_ows gives it, its first row the header) as variables named after them: city the texts of column "city", population its numbers (Floats). When the program is compiled the schema is checked and a definition written per column, so the rest of the program uses the columns by name and their kinds are type-checked like any variable (population c_at "x" is a type error). A malformed schema or table name stops the compiler: error[bad-columns]. Columns are found by their header when the program runs.
